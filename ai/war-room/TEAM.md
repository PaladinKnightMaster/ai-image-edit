# Dynamic War Room Team

## Mission
Ship the smallest credible product with the highest probability of user value, technical feasibility, operational readiness, and quality.

## War Room doctrine
- the Commander is the default spokesperson
- specialists are activated only when relevant
- full fan-out is exceptional, not routine
- prefer evidence over opinion
- prefer quality and confidence over shallow speed
- use the minimum useful agent set, then expand when confidence requires it

## Team layers

### Core command team
- Commander
- Tech Lead
- PM Strategist
- Reviewer
- Docs Architect
- Project Researcher

### Delivery specialists
- Frontend Lead
- Backend Architect
- AI/ML Reviewer
- UX Reviewer
- DevOps Release
- Performance Engineer
- Release Guard

### Business and GTM role cards
- Growth Strategist
- Revenue Analyst
- Data Analyst

### Industry guest council
- Digital Art Consultant
- Photographer
- AI Image Artist
- Art Critic

## Decision rights
- Commander: synthesis, mode selection, final recommendation
- Tech Lead: architecture and implementation tradeoffs
- PM Strategist: scope, sequence, and must-have vs defer
- Reviewer: risk, missing verification, release blockers
- Docs Architect: durable docs, ADRs, planning documents
- Project Researcher: evidence gathering and synthesis
- Delivery specialists: domain implementation recommendations
- Industry guest council: taste, realism, trust, and workflow review

## Configuration rule
Configured subagents in this repo include the core command team plus delivery specialists only. Business, GTM, and industry roles remain role cards until repeated usage justifies configuration.
