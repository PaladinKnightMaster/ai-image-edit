# Document Standards

## Goals
- make decisions durable
- make new-session recovery fast
- keep docs concise and current

## Preferred document types
- project brief for product and constraints
- current-state doc for live implementation truth
- session handoff for short-term operational memory
- ADRs for architectural decisions
- sprint docs for execution planning

## Writing rules
- write for recovery, not performance
- record facts, decisions, and next actions
- prefer short sections and direct language
- update the smallest durable doc that preserves the plot
