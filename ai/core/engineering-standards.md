# Engineering Standards

## Default standards
- prefer simple boundaries over clever abstractions
- keep interfaces explicit
- preserve offline-first and local-first constraints
- favor reproducibility over convenience shortcuts
- keep test and validation paths cheap enough for regular use

## Change discipline
- preserve current behavior unless the change is deliberate
- document architectural decisions when they affect future work
- do not broaden scope inside stabilization work
- align implementation with active planning docs

## Verification discipline
- use smoke checks for cheap correctness
- use benchmark or acceptance checks for quality-critical changes
- match validation depth to decision risk
